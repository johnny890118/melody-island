## 已重現的缺陷

- **YouTube 歌名顯示為 HTML 實體**：Mac Chrome 的原有歌單第 2 首《蒲公英的約定》把英文撇號顯示為 `&#39;`。YouTube 回傳的標題會保留至房間文件，原本直接把它當文字顯示。修正於搜尋結果、歌單、播放標題與可及名稱的共用顯示層解碼一次，仍由 React 以純文字渲染；不變更 Firestore 資料。已推送 `eb1f915`，並在[獨立 Staging](https://melody-island-stage-20261105-preview.vercel.app/) 用 Chrome 及實體 iPhone Safari 重整同一房間，確認畫面與 Chrome 可及名稱顯示 `Dandelion's Promise`。

## 自動化驗證（獨立於實機結果）

- TypeScript、ESLint、125 個單元測試、最佳化建置通過。
- 5 個 Firestore Rules 測試、合成資料備份／轉換／回滾演練通過，皆使用 `demo-melody-island` 模擬器。
- Playwright Chromium 25 通過／1 跳過；WebKit 24 通過／2 跳過。另跑 WebKit 同頁 Google 登入回歸 1 通過（Auth Emulator）。

- `eb1f915` 的遠端 PR CI 通過；同一提交的另一輪遠端 WebKit 因串流切換時出現兩個相同的 `noindex, nofollow` 而失敗。修正測試等待至少一個標記，且要求全部都禁止索引與追蹤；Chromium／WebKit 各重跑三次，共 6 通過。

## 正式上線前仍須確認

- 用可處置的房間完成新建、踢除、交接與密碼輪替。現有共聽房未被拿來做不可逆操作。
- 補齊真機競態、訪客權限拒絕、異常播放器恢復、iPhone 首頁觸控與效能。要量測實際音訊差，需同一時間錄取兩端輸出；媒體畫面和瀏覽器喇叭圖示無法提供此數據。
- 正式設定依[上線與復原手冊](../production-runbook.md)獨立審查：Firebase Auth 授權網域、App Check 服務端與 Firebase 服務分層、YouTube 方法限制及配額、邊緣節流。既有房間若仍有舊版文件，先審核相容性和備份還原，不以本輪合成演練代替。
